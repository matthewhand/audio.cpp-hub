DEPLOYMENT · 部署模式

三种部署形态：本机 systemd / Docker bridge / LXC host-network

同一份 Go 单二进制按宿主能力选择放置方式。无论 hub 跑在裸机、bridge 容器还是 LXC 宿主网络里，模型子进程始终只监听回环 127.0.0.1，对外只暴露 hub 自己的端口。

KEY POINT

放置决策：宿主 / 容器 / LXC

  • 本机：开发 / 非 GPU，单一二进制 + systemd 托管，hub 与引擎同在一个宿主用户下。
  • Docker bridge：生产 AMD，ports: 18080:18080 映射，只挂载 /dev/dri（HIP 另加 /dev/kfd）与权重只读目录。
  • LXC：改用 Compose network_mode: host，规避 init:true 设置的 ip_unprivileged_port_start 在 Proxmox LXC 内被拒绝的问题。

BOUNDARY · 端口与回环

子进程永远只在 127.0.0.1

hub 监听 :8080（本仓库开发副本与 Docker 镜像为 :18080）；实例端口从 instancePortBase=18090 起自动分配，绑定 127.0.0.1。容器内同理——引擎端口不随 ports: 对外发布，外部只能经 hub 访问。
