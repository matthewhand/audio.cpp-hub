# Nemotron 3.5 Transcribe hub catalog (experimental)

This source-only catalog addition registers the upstream `nemotron_transcribe` family as **offline ASR**, not the unrelated `nemotron_asr` 0.6B streaming family. It requires an `audiocpp_server` built with `nemotron_transcribe` enabled from a sufficiently recent audio.cpp revision. Adding the catalog does not replace or certify an existing server executable.

The catalog exposes transcription, translation, audio Q&A and language identification templates, optional word timestamps and speaker labels via request options. Upstream rejects timestamps or diarization for translation and Q&A. An instruction replaces the template instruction; if diarization is selected an explicit instruction must itself request speaker tags. The full structured result is available from the compatible engine's `/v1/tasks/run` as `custom_schema_output` or from the engine's `/v1/audio/transcriptions/details`; the hub UI's rendering of every structured field has not been validated. The current hub proxy supports bounded multipart model routing (public PR #172). Ordinary multipart transcription is routed unchanged; template/Q&A/timestamp options should use the engine JSON contract. Pipecat transport and full structured-result UI rendering remain separate acceptance work.

Packages are pinned to revision `304032f14e1e9e4042f5491d2d0194c044710bb7` of `Jmica/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B-GGUF`, with repository LFS SHA-256 hashes for the expert and encoder files. As of the repository metadata checked 2026-11-01, the smallest Q2 expert file plus F16 encoder totals 15,616,436,864 bytes, before model working memory, operating system and other allocations. That is not proof it fits a 16 GB RAM / 8 GB VRAM host. No weights were downloaded and no full-model inference performed. Check capacity before downloading weights; file sizes alone do not establish runtime capacity.

Engine reference reviewed: `0xShug0/audio.cpp` commit `c0cd77fa80285f8113883e0de06ffc781cf502f6`, `model_specs/nemotron_transcribe.json` and `docs/models/nemotron_transcribe.md`. Upstream describes the family as experimental and reports Vulkan full-model execution as untested. CPU expert offloading is opt-in, still requires device memory and host capacity, and is not proof that this system can run it.

Source changes only. No hub binaries, data, model services or network settings are modified by adding these catalog entries.

When configuring an instance, point the engine model path to the selected experts `.gguf` file, with the matching encoder `.gguf` beside it. The completed-download button uses the package's explicit primary decoder file, so the paired encoder is not mistaken for a second selectable model. Legacy packages retain their directory path under the configured model root.
